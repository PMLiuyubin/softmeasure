## 4. 机理计算和知识库

### 4.1 机理计算

原页两套计算，必须继续分开。

- 机理算子库：锁温式  
  `含量 = 67.55 + 0.59×(回流 − 6.53) + (−2.40)×(侧线 − 3.85)`  
  系数只在 `config/product.json` 的 `slope_reference`。粉线、黄线、蓝线、设定推演用它。
- 逐板求解：`mech_stage.js`。第一页四股实测流量（中位不加条件）。第二页才用回流给定和侧线给定。空的手填项不进入计算。离开中位后相对化验的均方根是 10.56。进料低于 7.5 t/h 的 44 张不进这两遍。逐板结果只在化验旁边对照，不替换绿线，不进入两小时报值。

加控制后的离开中位均方根是 1.64，仍未小于等于 1.5。页面保持这个数，不把它写成已经通过。

### 4.2 工艺知识库

原页页签：新建、实体、工况实例、全部规则、成串、标签。  
可按状态（待核对、已入库、暂不入库）和层级（准入与工况、残差时序、根因诊断）筛选。  
「重新挖掘」保持离线命令。打开页面不执行挖掘，不导入 `core_bases.mining`。

知识库是应用层，不是第六个底座。它读取挖掘结果和标记，自己不重算预报。

## 5. 五个底座怎么承接这些功能

| 底座 | 代码 | 页面用它做什么 |
|---|---|---|
| dataset | `core_bases/dataset` | 快照、验收窗切分、四个在线标记、资料库点位和化验表。实时点禁止写入快照。 |
| mechanism | `core_bases/mechanism` | 只算锁温式，以及黄线、蓝线的组合。逐板不进这个包。 |
| predict | `core_bases/predict` | 读已签发的七条预报。逐点推理开关关闭，打开页面不训练。 |
| evaluate | `core_bases/evaluate` | 只在 2878 个五分钟点上算决定系数和均方根。15 分钟的 960 点只用于画图。 |
| mining | `core_bases/mining` | 仅离线。在线接口读上次落盘的 `mining_last.json`，不执行挖掘。 |

应用层 `application/` 负责菜单接口、实时缓存、知识库、装置日志、角色。底座不反向调用应用层。`experiments/` 里的历史训练脚本，在线服务不导入。

浏览器不写含量公式，不写第二份 67.55、0.59、−2.40。

## 7. 每一组怎么基于底座实现

### 7.1 大屏

`GET /api/screen` 由应用层组装，内部读 evaluate、predict、mechanism、知识库实体。

塔区大屏中间是甲基萘塔 T-2101：最近时刻的到达近红外、绿线、粉线，以及验收决定系数 0.29、均方根 0.69。知识库里其余塔实体列在周围，状态写「未接入实测」，不显示编造的纯度。不写设定值。

预测指标用 evaluate 的七条线全表，绿线在第一行，并注明窗是 2026-09-05 至 2026-09-14、五分钟、2878 点。

### 7.2 单塔

七线八个页签优先做完，因为这是原主流程。

- 并列：`GET /api/series` 已返回 960 点的七条值和到达近红外。接口要补上残差（预报减到达近红外）、化验点和按日指标，前端只负责勾选和画图。纵轴围绕含量，不从 0 起画。
- 分歧时段：同一序列上由接口标出绿线与到达近红外偏差大的时段。
- 设定推演：`GET /api/mechanism/lock?reflux=&side=` 只调锁温式。不读绿线文件，不把给定写进快照。
- 工况分解：`GET /api/dataset/marks` 返回四个标记的原文：是、否、窗口不足。不重估阈值，不用标记隐藏黄线或蓝线。
- 验收窗、报出条件、底座：读 `GET /api/foundation`。
- 实时入口：已有 `POST /api/realtime/point` 和 `GET /api/realtime/recent`。字段为时间、近红外、进料、回流、侧线、塔顶采出、塔顶温度、侧线温度、塔釜温度。未知列拒绝。没有绿线时黄线、蓝线留空。粉线在回流和侧线都有数时仍可算。缓存按写入时间保留 7 天，文件是 `data/realtime_cache.pkl`。

运行监视用同一时刻的绿线、到达近红外和四个标记。

质量判定、报警、合格率、残差漂移的阈值放配置。统计列必须写明是到达近红外还是绿线。原页 70% 和 ±0.4% 是演示阈值，侧线验收不是这一套。验收仍是绿线的 0.29 和 0.69。两套门槛分开展示，不能混成「达标」。

预测追溯和历史趋势用已签发预报按时刻对齐，不另画一套测试集冒充验收窗。

点位波形、明细、近红外、罐区、原料组分：`GET /api/factory/table?file=` 读 `factory.db`，列名用 `column_map` 还原。没有该表就写缺文件，不回放合成序列。

物料衡算、相平衡、能量衡算、动态约束：只用资料库里的实测流量和温度，以及知识库关系。缺热值、比热、炉效率时写明缺少，不补模拟物性。这些页不进入两小时报值。

机理计算页保持两页。逐板模块继续独立，与锁温式并排。10.56 和 1.64 标成离开中位后相对化验的均方根。

纯度导入写入应用层导入表。禁止写入 `official_fru2h_dataset.pkl`。

模型调优只读已有实验预报的验收指标。此页不训练，浏览器不打开 pkl。

### 7.3 多塔

塔档案、组合、复制、模型库的主数据是知识库实体和关系。甲基萘塔绑定绿线文件和验收指标。其余塔可以建档、编组、走复制步骤，但没有实测和已签发预报时，启用按钮不可用，也不生成第二套 0.29 / 0.69。映射未通过时不得启用。训练若发生，放在离线脚本，不在浏览器里跑。

### 7.4 全工艺级联

物流和设备用知识库已有对象：原料洗油进料、甲基萘塔回流、侧线采出、塔顶萘馏分、塔釜出料、中质洗油塔、管式炉、冷凝器、回流罐。

流程组态编辑这些关系，保存到应用层，并写装置日志。未通过校验的边不传递。

级联预测、态势、追溯、影响传导、安全约束都读这些关系。上游没有已签发预报时，页面写「上游未接入实测，不传递」，下游不出现编造的到达值。切断、缺测、通信中断、开停车只改页面上的传递状态。所有页都不写 DCS 设定值。

### 7.5 智能运维

知识库六个页签接 `knowledge.db` 的只读接口。新建规则走 `POST`，不调用挖掘包。重新挖掘保持离线。

智能告警、智能调优、运行解读、建模解读用绿线、到达近红外、四个标记和规则标题生成说明。确认只追加装置日志。

智能对话只检索知识库和底座说明。对话不能改公式，不能改验收结果。

装置日志记录告警确认、班报确认、实时写入、组态变更。只追加。

### 7.6 接入、报表、系统

接口桩列出真实路径：`/api/foundation`、`/api/series`、`/api/compute/lines`、`/api/realtime/point`、`/api/realtime/recent`、`/api/kb/sources`，以及第 8 节待建接口。本机 8780 通才标已接通。

OPC、MES 显示资料库和点位是否已入库。未接实时链路就标未接通。

模型嵌入页写明：逐点推理关闭，预报来自已签发文件，浏览器不读 pkl。

批次对照把侧线化验和同一时刻的绿线、到达近红外放在一起。

班报按日汇总，并写明汇总的是验收窗还是实时缓存。班长确认后写日志，不改化验原值。查看角色不能确认。

点位字典至少包括：进料 `2770_FT21101`、回流 `2770_FT21102`、侧线 `2770_FT21103`、塔顶采出 `2770_FT21105`、塔顶温度 `2770_TE21104`、侧线温度 `2770_TE21105`、塔釜温度 `2770_TE21108`，近红外列 `JJN_当时`。可从资料库点位表追加。

告警配置和角色放应用层表。三个角色的权限与原页一致。
